## 4. Android 12+ handling and limitations

Per [flutter_native_splash](https://pub.dev/packages/flutter_native_splash) docs:

- Android 12+ uses a separate API: opaque window **color**, centered **icon** (circularly clipped), optional icon background, optional branding image (800×320).
- **Full-bleed custom illustrations are not supported** on Android 12+. The dome / arches / palm scene from the splash artwork cannot be shown as a full-bleed background on API 31+.
- Icon sizing: without icon background, prefer ~1152×1152 with content inside a ~768px circle; with background, ~960×960 inside ~640px circle.
- Pre–Android 12 devices get the classic centered image on the burgundy color.

**What we ship:** burgundy `#3B0B0B` + centered keyhole icon. Architecture scene is not forced/cropped on Android 12.

## 7. Details that could not be matched (and why)

- **Android 12 full splash scene** (dome/palm): platform forbids full-bleed splash images; documented above.
- **Exact metallic logo lighting** on splash vs auth: auth uses logo cropped onto black; splash uses padded square icon on burgundy for circular mask safety.
- **Reset deep-link token**: UI matches screenshot; if `token` query is missing, toast asks user to open email link (API still requires token). No invented token field on the screen (screenshot has no token input).
